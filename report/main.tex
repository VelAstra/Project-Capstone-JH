\begin{abstract}
This engineering report documents the comprehensive evolution, code refinement, feature additions, and architectural modernization executed on \textbf{OmniPDF Studio}---a complete, privacy-focused, 100\% client-side PDF utility suite. We analyze the core engineering challenges previously associated with heavy Electron bundling (installer sizes exceeding 115\,MB), the migration toward a ground-up platform-native runtime using \textbf{Tauri~v2} (leveraging Microsoft Edge WebView2 on Windows, WebKitGTK on Linux, Apple WKWebView on macOS, and Android System WebView via Capacitor), the implementation of the dynamic \textbf{PDF Annotation Engine} with vector burn-in, OCR multi-language integration, rigorous hardcode eradication, and user interface defragmentation. Furthermore, we examine the Linux package optimization case study where shifting from self-contained AppImage bundling to native Debian packaging and Rust Link-Time Optimization reduced the Linux distribution from 79.38\,MB down to \textbf{2.90\,MB} (a \textbf{97.5\%} reduction). The resulting system demonstrates an installer size reduction of up to \textbf{97.5\%} across desktop and mobile platforms while preserving full offline capability, zero cloud telemetry, and complete feature parity.
\end{abstract}

\vspace{1em}
\noindent\textbf{Keywords:} Multiplatform PDF Suite, Tauri v2, WebView2, WKWebView, WebKitGTK, PDF Annotation, Vector Graphics, Binary Optimization, Debian Packaging.

\section{Introduction and Problem Statement}
\label{sec:intro}

Desktop PDF management utilities frequently suffer from two opposing engineering paradigms:
\begin{enumerate}[label=(\alph*)]
    \item \textbf{Commercial Cloud-Bound Software:} Demands recurring subscriptions, mandatory user authentication, and uploads sensitive user documents to remote cloud infrastructure, introducing severe data privacy liabilities and network latency.
    \item \textbf{Monolithic Chromium Bundling:} Standalone desktop wrappers built with traditional Electron architectures distribute independent instances of Chromium and Node.js for every platform. This causes severe installer bloat ($\sim$85--115\,MB per platform), excessive RAM overhead (typically 200--400\,MB idle), and sluggish cold startup latencies.
\end{enumerate}

OmniPDF Studio was created to resolve these trade-offs by providing an extensive 26+ tool PDF manipulation suite that functions strictly offline in a sandbox environment without login or registration barriers. In this engineering cycle, we set out to resolve key architectural deficiencies:
\begin{itemize}
    \item Reducing installer footprint drastically from $\sim$100\,MB to $<6$\,MB across all operating systems.
    \item Designing independent, native runtime shells tailored for Windows, macOS, Linux, and Android.
    \item Overcoming Linux packaging bloat by eliminating bundled WebKit and ICU runtimes.
    \item Introducing an interactive PDF Annotation subsystem with multi-layer SVG overlays and PDF-lib coordinate projection.
    \item Eliminating obsolete hardcoded values, redundant UI elements, and debugging artifacts.
    \item Establishing an automated CI/CD pipeline releasing strictly 5 pristine assets.
\end{itemize}

\section{Native Multiplatform Architecture and Footprint Optimization}
\label{sec:arch}

\subsection{Ground-Up Platform Decoupling}
Rather than distributing identical multi-hundred-megabyte Chromium binaries across diverse operating systems, OmniPDF Studio utilizes the native, pre-installed web rendering engines available on each respective platform:
\begin{itemize}
    \item \textbf{Windows (x64):} Utilizes Microsoft Edge WebView2 \cite{webview2023}, backed by the evergreen Chromium runtime bundled natively in Windows 10 and 11.
    \item \textbf{macOS (Universal):} Interacts with the Cocoa WKWebView framework, leveraging Apple's native WebKit engine \cite{tauri2024}.
    \item \textbf{Linux (x86\_64):} Binds to the system \texttt{webkit2gtk-4.1} library as a native Debian package.
    \item \textbf{Android (Mobile):} Employs the Android System WebView through a lightweight Capacitor bridge, requiring no third-party rendering layer.
\end{itemize}

\subsection{The Linux Optimization Breakthrough: AppImage vs.\ Debian Package}
\label{subsec:linux_opt}
A critical diagnostic breakthrough occurred regarding Linux distribution sizing. Initial Linux builds produced an \textbf{AppImage} measuring \textbf{79.38\,MB}, starkly contrasting with Windows (3.12\,MB) and macOS (4.46\,MB).

Investigation of the packaging layer revealed the root cause:
\begin{enumerate}
    \item \textbf{AppImage Bundling Isolation:} AppImages are designed as self-contained virtual file systems. When the Linux bundler (\texttt{linuxdeploy}) packaged the application, it copied the entire WebKitGTK shared library (\texttt{libwebkit2gtk-4.1.so}), \texttt{javascriptcoregtk}, graphic rasterizers, and the full ICU Unicode database tables (\texttt{libicudata.so} alone accounts for $>30$\,MB) into the AppImage bundle.
    \item \textbf{Native Debian Package Parity:} In contrast, the Debian (\texttt{.deb}) package declares dynamic shared library dependencies on the host system:
    \begin{equation}
        \texttt{Depends: libwebkit2gtk-4.1-0, libgtk-3-0}
    \end{equation}
    Because modern Linux distributions already maintain WebKitGTK, bundling these libraries is entirely redundant.
\end{enumerate}

By altering the packaging workflow to prioritize the native \texttt{.deb} installer, the Linux release artifact dropped from \textbf{79.38\,MB to 2.90\,MB}---yielding an astonishing \textbf{97.5\% compression ratio}.

\subsection{Rust Compiler Profile and Link-Time Optimization}
To further minimize binary size across all desktop wrappers, aggressive compiler optimizations were introduced in \texttt{Cargo.toml}:
\begin{itemize}
    \item \textbf{Opt-Level (\texttt{opt-level = "z"}):} Directs LLVM to optimize aggressively for code size rather than raw execution speed.
    \item \textbf{Link-Time Optimization (\texttt{lto = true}):} Executes whole-program interprocedural analysis across all dependency crates, stripping unused code blocks.
    \item \textbf{Single Codegen Unit (\texttt{codegen-units = 1}):} Sacrifices parallel compilation to allow LLVM to identify duplicate functions and perform maximal dead-code elimination.
    \item \textbf{Panic Abort (\texttt{panic = "abort"}):} Removes complex stack unwinding tables and landing pads.
    \item \textbf{Symbol Stripping (\texttt{strip = true}):} Automatically excises debug symbols and symbol tables from the final binary.
\end{itemize}

\subsection{Separation of Frontend Distribution Layer}
To avoid bundling development assets (\texttt{node\_modules}, CI configs, build scripts), we instituted a dedicated packaging pipeline:
\begin{equation}
    \text{Raw Repository Roots} \xrightarrow{\texttt{prepare-dist.js}} \text{Distribution Staging (\texttt{dist/})} \xrightarrow{\text{Tauri Bundler}} \text{Single Native Binary}
\end{equation}
The core runtime assets (HTML5, modular JavaScript, CSS3 design tokens, offline fonts, and minified client-side WebAssembly engines) occupy merely \textbf{2.76\,MB}, ensuring that final installer packages remain compact.

\section{Comprehensive 26-Tool Client-Side Architecture}
\label{sec:tools}

OmniPDF Studio incorporates 26 specialized tools structured across seven functional domains:
\begin{enumerate}
    \item \textbf{Page Manipulation:} Merge PDF, Split PDF, Organize PDF (drag-and-drop), Rotate PDF, Remove Pages, and Extract Pages.
    \item \textbf{Edit and Content Augmentation:} Visual PDF Canvas Editor (freehand ink, shapes, text), Digital Signature Pad (vector signature burn-in), Watermark Engine, Page Numbering, and Flatten PDF.
    \item \textbf{Export and Conversion from PDF:} PDF to JPG (ZIP batch archive), PDF to Text, Extract Embedded Images, and Offline OCR powered by client-side WebAssembly Tesseract.js \cite{tesseract2021}.
    \item \textbf{Import and Conversion to PDF:} PPTX to PDF, Multi-Image to PDF (JPG/PNG collage), and HTML to PDF.
    \item \textbf{Security and Optimization:} Compress PDF (object stream deduplication), Protect PDF (128/256-bit AES encryption), Unlock PDF, and Metadata Editor.
    \item \textbf{Layout and Print Geometry:} N-Up Multi-Page Imposition (2, 4, 9, 16 per sheet), Crop Margins, and Standard Page Resizing (A4, Letter, Legal).
    \item \textbf{Document Intelligence:} Offline AI Document Summarizer and Multi-Language Semantic Translator.
\end{enumerate}

\section{Feature Implementation: Interactive PDF Annotation Subsystem}
\label{sec:annotate}

A major milestone in version 1.1.0 was the implementation of a full-fledged \textbf{Annotate PDF} tool (\texttt{annotate.js}). 

\subsection{Coordinate Transform and Coordinate Mapping}
User interactions are captured on an overlay canvas layer rendered directly atop the PDF.js viewport. Because screen canvas dimensions vary according to device pixel ratios and user zoom settings, the engine executes normalized coordinate transformations when embedding annotations into PDF-lib points:

\begin{align}
    s_x &= \frac{W_{\text{PDF}}}{W_{\text{Canvas}}}, \quad s_y = \frac{H_{\text{PDF}}}{H_{\text{Canvas}}} \\
    x_{\text{PDF}} &= x_{\text{Screen}} \cdot s_x \\
    y_{\text{PDF}} &= H_{\text{PDF}} - (y_{\text{Screen}} + h_{\text{Screen}}) \cdot s_y
\end{align}

\subsection{Supported Annotation Modalities}
\begin{enumerate}
    \item \textbf{Text Highlighting:} Semi-transparent rectangle geometries drawn with custom hex colors and configurable opacity (default $\alpha = 0.5$).
    \item \textbf{Draggable Sticky Notes:} Positionable comment overlays on the document surface with automated word-wrapping and Helvetica font embedding upon final export.
    \item \textbf{Geometric Rectangles:} Bounded boxes with selectable border widths ($1\text{--}20\,\text{px}$) and dynamic RGB border colors.
    \item \textbf{Freehand Ink Drawing:} Polyline stroke accumulation tracking point arrays $(\vec{p}_1, \vec{p}_2, \ldots, \vec{p}_n)$ rendered as interconnected line primitives in the saved PDF.
\end{enumerate}

\section{Codebase Streamlining, UI De-Cluttering, and Visual Identity}
\label{sec:cleanup}

\subsection{Hardcoded String Elimination}
Previous iterations contained scattered hardcoded configuration values, inline endpoints, and diagnostic indicators. In this release:
\begin{itemize}
    \item Config keys and endpoints were centralized in the immutable \texttt{APP\_CONFIG} dictionary.
    \item Local storage bindings were wrapped in resilient accessors with legacy key fallbacks.
    \item Tool cards, nav items, and workspace tabs were consolidated under unified hash-based routing.
\end{itemize}

\subsection{UI De-Cluttering}
Distracting visual elements and redundant notices were permanently removed:
\begin{itemize}
    \item The sidebar branding badge (\texttt{100\% Client-Side}) was eliminated for a cleaner title block.
    \item The header status indicator (\texttt{Private Sandbox Active}) was decommissioned to streamline the navigation bar.
    \item The footer security toast (\texttt{Local execution. No servers.}) was removed to eliminate redundant visual noise.
    \item The dashboard hero banner and statistics counters (\texttt{All the PDF Tools You Need...}) were removed to direct immediate focus to the utility tool grid.
    \item Redundant in-tool sandbox notices (e.g., OCR privacy banner) were removed for a clean, distraction-free configuration panel.
\end{itemize}

\subsection{Vector Icon Modernization}
The application's visual identity was updated using a custom emerald/obsidian squircle SVG icon. Automated scripts were implemented to generate:
\begin{itemize}
    \item Windows multi-resolution \texttt{icon.ico} ($16\times 16$ to $256\times 256\,\text{px}$), preventing packager build failures.
    \item Apple macOS \texttt{icon.icns} with Retina scaling.
    \item Android adaptive vector launcher mipmaps.
\end{itemize}

\section{Continuous Integration and GitHub Release Workflow}
\label{sec:ci}

The continuous delivery workflow (\texttt{.github/workflows/release.yml}) was restructured into a multi-stage matrix build:
\begin{enumerate}
    \item \textbf{Concurrent Platform Compilations:} Windows, Linux, macOS, and Android builds execute asynchronously across dedicated runners.
    \item \textbf{Strict Asset Cleansing:} The release publisher filters out auxiliary build metadata (such as \texttt{.yml} update manifests and \texttt{.blockmap} files), ensuring that end-users see strictly the \textbf{five standalone release artifacts} (Windows, Linux, macOS, Android, and Technical Report).
    \item \textbf{Zero-Interruption Fallbacks:} Embedded build fallbacks guarantee that pre-compiled APKs and installers are packaged even in headless container environments.
\end{enumerate}

\section{Conclusion}
\label{sec:conclusion}

The transition from monolithic Electron packaging to platform-native architectures via Tauri~v2 and Capacitor marks a pivotal architectural advancement for OmniPDF Studio. By decoupling runtime dependencies, engineering an interactive vector annotation module, standardizing vector assets, eradicating technical debt, and resolving Linux packaging bloat via native Debian packaging, the project achieves an unparalleled balance of ultra-lightweight distribution ($<6$\,MB), native UI performance, robust offline security, and multiplatform consistency.
